# Contributing

This file is for work on the themes, the runtime and the tools. To use the theme in an app,
read [`AGENTS.md`](AGENTS.md).

The tools need Python 3.11 or newer and only the standard library (`ui-theme/update.py`
itself runs on 3.9+). The browser tests need Chrome, Chromium or Edge.

## Layout

## The loop

```
# edit src/ or adapters/
python tools/check_contrast.py --theme <slug>   # while tuning a theme
python tools/sync_theme.py build                # regenerate everything
python tools/sync_theme.py check                # generated files current, docs consistent
python -m unittest discover -s tests
python tests/run_browser_tests.py
python tools/lint_colors.py ui-theme src
python -m build                                 # the wheel and sdist into dist/ (not committed)
python tools/selftest_forgeui.py --wheel dist/themeforge-*.whl   # vendors the examples with the built wheel
python -m http.server 8000                      # then /specimen/ and /tests/runtime.html
```

CI runs the same checks on every push and pull request, and builds the wheel on Linux and Windows.
Each pull request also uploads a `specimen-screenshots` artifact: `shots/before/` (the base branch) and
`shots/after/` (the pull request), each with every theme's PNG and a `gallery.png`, to compare by eye.

## Adding a theme

1. Copy `docs/theme-template.css` to `src/css/theme-<slug>.css` and fill in every token. The
   template lists each token with the contrast floor it must meet.
2. Add an entry to `src/themes.json`: `slug`, `name`, `description`, `family`, `ground`
   (`oled`, `dark` or `light`), `colorScheme`, `themeColor` (usually `--surface-0`), `set`
   (`core` or `opt-in`; new themes are opt-in), `swatch`, `fonts`, `css`, and
   `contrastProfile` only if it is not `standard`.
3. `python tools/check_contrast.py --theme <slug> --fail-on any` until it passes. A high-contrast
   theme names `"contrastProfile": "high"` (7:1 text, solid colours; see `docs/THEMES.md`).
4. `python tools/sync_theme.py build`, then look at it in the specimen.
5. A dark/light pair shares a `family`; the runtime's `toggleFamily()` switches between them.

Rules for theme files: every contract token is defined (a theme that leaves one out inherits
Purple's value, which is almost never right); tokens outside the contract are allowed but no
component may depend on them; `--z-*` are never overridden.

## Changing the contract

Adding a token: define it in `theme-base.css` (preferably derived from existing tokens with
`var()` or `color-mix()`, so no theme file has to change), add a contrast check if it carries
text or a state, describe its group in `GROUP_NOTES` in `tools/sync_theme.py` (which writes
`docs/TOKENS.md`), and bump the minor version.
Renaming or removing a token breaks apps: major version only.

## Releasing

1. Set `version` in `src/themes.json`, add a `CHANGELOG.md` entry, update the pinned version
   in the docs (`check` lists any stale ones), the `version` in the examples' `forgeui.json` if the
   minor changed (the unit tests fail otherwise), run `build`, and commit.
2. Tag the commit `vX.Y.Z` and push the tag. `update.py` installs the newest tag by default,
   and jsDelivr serves tags.
3. `python tools/screenshots.py` refreshes `docs/images/gallery.png` when the look changed.

## Publishing to PyPI

The distribution is `themeforge` (the import package is `forgeui`; the name `forgeui` on PyPI is an
unrelated project). Publishing is off until the maintainer turns it on. The `pypi` job in
`.github/workflows/release.yml` uploads the sdist and wheel that the release job built, with
trusted publishing, so no token is stored anywhere. It runs only for a new release and only when
the repository variable `PYPI_PUBLISH` is `true`. To turn it on:

1. On pypi.org, create the project `themeforge` with a trusted publisher for this repository: for a
   first upload use a pending publisher (Account settings, Publishing). Owner `LaserLloyd`,
   repository `ThemeForge`, workflow `release.yml`, environment `pypi`.
2. In the GitHub repository, Settings, Environments: create an environment named `pypi` (required
   reviewers there add a manual approval before each upload).
3. In Settings, Secrets and variables, Actions, Variables: add the repository variable
   `PYPI_PUBLISH` with the value `true`.

The next version merged to `main` is then published to GitHub and to PyPI. A PyPI version cannot be
replaced once uploaded, only yanked, so CI runs `twine check` on every push. To pause publishing,
delete the variable or set it to anything but `true`. Once the project is live, switch the install
lines in the docs from the release tag to `pip install themeforge`.

## Keeping copies in apps

Each app keeps a `forgeui.json` in its own repository and runs `python -m forgeui vendor`
(`--check` in CI); see `docs/THEME_SYSTEM.md`. Apps without pip use `ui-theme/update.py`. The
machine-local app registry (`sync_theme.py install`) was removed in 2.0.

## Python version

`ui-theme/update.py` and the `themeforge` package (import name `forgeui`) run on Python 3.9 or newer (CI runs the `forgeui`
tests on 3.9); the tools in `tools/` need 3.11. Mind `Path.write_text(newline=)` and other 3.10+
conveniences in `forgeui/`.
